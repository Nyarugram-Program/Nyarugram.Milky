# Nyarugram.Milky 九项复核问题修复与验收 Prompt

你负责直接修复 Nyarugram.Milky 当前实现，完成回归并更新实际交付记录。目标是可靠的基础账号能力、私聊和群聊消息收发，以及与现有 Nyarugram Android 客户端互通的真实双向语音电话。

先阅读仓库根目录 AGENTS.md、README.md，以及 Docs/IMPLEMENTATION.md、Docs/CALLS.md、Docs/MEDIA-PROTOCOL.md、Docs/SUPPORT-MATRIX.md 和 Docs/DELIVERY-REPORT.md。结合实际源码核实下面的问题，行号可能随修改变化。保留已有用户修改。

当前复核已确认解决方案可构建，现有 23 项测试通过，但测试使用的假后端掩盖了真实入口错误，也未覆盖持久恢复、投递失败和完整呼叫协商。修复需要增加针对这些缺口的回归。

## 强制边界

- 对外按锁定 Milky 版本提供 HTTP JSON 与事件。访问 Nyarugram 后端坚持 Protobuf-only，禁止 JSON-TL、已弃用 REST、MTProto 和公共服务回退。
- 业务持久化坚持 PostgreSQL-only，不引入 JSON 文件数据库、SQLite 或整库快照桥。
- 独立构建，协议固定副本记录来源、版本和 SHA-256。开发时可核对同级 Botgram.Backend 与 Botgram，构建和运行不依赖同级源码目录。
- 新下载的依赖、工具和缓存全部位于 D 盘，默认 D:\BotgramBuild。媒体依赖固定版本、来源、许可证与校验值。
- 测试使用隔离账号、数据库和端口。运行现有集成测试前检查其建库和删库逻辑，禁止操作正式用户数据。
- 文档中不写实际公网服务地址、真实凭据或默认公共连接目标。README.md 和 AGENTS.md 保留根目录，普通说明放 Docs/，本任务 Prompt 保留 Prompt/。
- 本任务授权源码修复、隔离验证和构建。正式部署、发布及正式数据迁移需要遵循已有明确授权范围。

## 一、修复账号查询入口

问题位于 src/Nyarugram.Milky.Core/MilkyActions.cs 的 LoginInfoAsync。当前通过 BackendRpc 把 AccountMe 发往 /api/v1/rpc，而真实 PostgreSQL 后端在 /api/v1/account 处理它。假后端在业务入口额外接受了 AccountMe。

要求完成以下工作。

- 使用正确账号入口，复用现有 AccountMeAsync 等实现，并保留请求开始、响应返回和结果交付前的账号及代际检查。
- 假后端严格匹配真实后端的入口和操作边界，错误入口必须返回真实契约对应错误。
- 验证 get_login_info 的成功结果、失效令牌、请求期间退出或切换账号、迟到响应。

## 二、实现消息发送的持久幂等与未知结果恢复

问题位于 MilkyActions.SendAsync。random_id 仅在方法内保存，第三次 BackendException 被普通错误分支处理，SendOutcomeUnknown 路径实际无法按预期执行。

- 在发送后端请求之前，把操作身份、账号作用域、完整不可变请求、请求摘要、random_id 和状态可靠写入 PostgreSQL。
- 为 Milky 调用提供有文档和类型定义的可选幂等扩展键。同键同内容复用原操作，同键不同内容冲突，并发同键请求只能驱动同一个逻辑操作。
- 完整保留有符号 int64 random_id，拒绝 0，不通过浮点处理。
- 根据实际传输与错误语义区分明确拒绝、可安全重试和提交结果未知。请求超时、丢响应、调用方取消及进程退出后均应能对账。
- 后端重试复用原 random_id 和原请求内容。旧消息重试返回的原事件 pts 不得被当成当前同步水位。
- 标准 Milky 请求没有幂等键时，准确说明调用方再次请求的边界，不能用文本哈希合并有意重复发送。
- 验证后端已提交但响应丢失、进程重启、同键并发、不同内容冲突，以及最终失败的错误分类和恢复入口。

## 三、防止同步临时失败导致永久漏消息

问题位于 SyncService.ApplyPageAsync。消息映射或资料查询抛出异常后直接 continue，整页游标仍会推进。

- 对暂时失败重试整页，或者先持久化足够恢复的待处理记录，再推进游标。
- 明确区分暂时网络错误、权限变化、已删除对象、确定不支持的内容和密文占位语义，避免无限卡页及静默遗漏。
- 确保消息投影、待投递事件和游标事务边界正确。呼叫更新也需要可靠重放，不能因捕获异常后推进同步水位而丢失。
- 验证资料查询暂时失败、恢复后重试、落库失败、进程中断、重复差分以及多页补偿。
- E2EE 内容遵守现有未开启方的占位要求，不输出明文或信封内部数据，不恢复按产品约定永久不可读的旧消息。

## 四、补齐事件的持久投递与重连恢复

问题位于 OutboxDispatcher.DrainAsync、EventBus 和 MilkyEndpoints.HandleEventAsync。Publish 仅入内存队列，调用方忽略接受数量后立即 MarkDelivered，重连也没有重放流程。

- 设计并实现明确的持久消费位置、保留窗口和重放契约，适用于 SSE 与正向 WebSocket。
- 如需游标、确认或恢复扩展，使用明确命名的 Nyarugram 扩展，并保持标准 Milky 事件兼容。为普通应用端准确说明能力边界。
- 处理每个消费者的投递进度、慢消费者、断线、全体拒收、内存队列溢出和进程退出。不能因一个消费者接受而让其他消费者永久漏事件。
- 对无法确认对端处理的网络窗口，提供稳定事件标识与可恢复的至少一次语义。不要声称严格恰好一次。
- 消息事件也应向应用暴露可用于去重的稳定标识，明确其与数据库 event_seq 的关系。
- 无消费者时不能以已交付名义静默退休事件。保留期过期应有明确状态、监控及恢复或重新同步方式。
- 验证入队后进程退出、写 socket 失败、两个消费者之一掉线、超过队列容量、无消费者后重连和保留期边界。

## 五、完成真实呼叫协商和双向媒体

当前 CallService 缺少 received_call、confirm_call 等关键操作。媒体 StartAsync 的出站信令回调为空，默认引擎拒绝发起和接听，真实语音尚未实现。

- 核对现有 Android VoIPService、实际媒体引擎及后端 phone 操作，完成来电确认、接听、主叫确认、双向信令和终态流程。
- 使用兼容且成熟的媒体引擎，通过绑定或隔离媒体进程接入。补充真正需要的端点、协议层、库版本、P2P 策略、STUN/TURN 配置和媒体生命周期参数。
- 完成 DH 参数与对端公钥检查、g_a_hash 校验及密钥指纹验证。协商或密钥验证失败必须终止当前流程，不能捕获失败后继续使用空密钥启动媒体。
- 保存并管理实际媒体会话句柄。挂断、失败、账号退出和进程恢复均释放音频、连接、子进程、任务和短期令牌。
- 媒体 WebSocket 面向实际引擎接口，解除对 LoopbackMediaEngine 的专用耦合，执行格式、帧大小、方向、令牌权限和缓冲上限校验。
- Loopback 仅用于本地管线验证，能力声明保持准确。真实语音需要与现有客户端完成双向已知音频收发后才能标记可用。
- 视频继续按独立能力验收。没有视频实现时在请求后端前明确拒绝。
- 至少覆盖机器人呼叫手机、手机呼叫机器人、响铃拒接后双方立即重拨、忙线、取消、超时、P2P 和 TURN 中继。

真实媒体是本任务交付目标，不能用接口占位作为完成结果。如果确有外部阻碍，先完成其他可执行修复，报告精确阻碍、已完成的技术验证和仍需的输入，不得伪造设备或真实服务测试结果。

## 六、修复发起呼叫的持久幂等与并发

当前 CallService.StartAsync 使用 null random_id 占用幂等键，然后才生成新随机 ID、DH 私钥和后端请求，未完成记录无法恢复。

- 请求后端前持久化原 random_id、不可变请求、加密 DH 私钥、公钥承诺、操作身份与阶段。
- 同键同内容包括进程重启后的重试必须恢复同一呼叫，不能重新生成 DH 材料。不同内容冲突。
- 未完成操作具备可靠的并发领取、租约或事务串行机制，处理执行者中途退出。
- 后端响应、呼叫投影和操作完成状态应可恢复，避免后端已创建呼叫而本地没有身份映射。
- 根据现有后端的真实 random_id 去重及查询能力实现对账。契约不足时明确增加必要的 typed Protobuf 能力，并遵循后端 AGENTS.md，不访问业务数据库绕过接口。
- 验证同键并发、后端提交后丢响应、每个持久化阶段中断、重启恢复和参数冲突。

## 七、修复呼叫重启清理和未知挂断结果

当前 RestoreAsync 恢复原 session.Generation，而 FailStaleAsync 只清理 generation 不同的呼叫，所以普通进程重启不会触发预期清理。EndAsync 捕获后端错误后直接将本地标记 ended，也没有持续对账。

- 区分账号登录代际与运行进程实例。恢复同一会话时，也能识别前一进程遗留的媒体和呼叫。
- 先确认后端状态，再恢复确实可恢复的呼叫或可靠结束旧呼叫。需要时补充最小 Protobuf 查询契约。
- 丢响应、网络不可达和其他临时错误保留待确认状态及可重试任务，不能把本地结束作为后端已释放占线的证据。
- 本地媒体资源及时释放，后端对账继续可靠执行。处理重复终态、迟到接听和旧呼叫更新，不能影响新电话。
- 验证同 generation 重启、后端挂断失败、后端已挂断但响应丢失、进程异常退出及恢复后的双向重拨。

## 八、修复资料缓存和迟到结果的账号隔离

当前 IdentityResolver 的缓存键只有 user/group 数字 ID，ProfileCache 是单例，未按服务器、账号和代际隔离。

- 统一缓存作用域，包含服务器身份、账号 UUID 和必要的会话代际，涵盖用户、群及成员资料等关联缓存。
- 退出或切换账号时失效旧作用域。迟到查询不能污染新作用域，也不能绕过新账号权限。
- 检查缓存命中路径、后端返回后的数据库写入路径、同步提交及最终 UI/API/事件交付路径的上下文校验。
- 核对恢复账号时的选择逻辑，不能仅取最早账号或忽略当前配置的服务器身份。
- 验证两个账号访问相同数字身份但权限或资料不同、切换期间迟到响应、重新登录和服务器配置变化。

## 九、修复呼叫事件去重冲突与事务边界

当前 EmitAsync 的 event_id 只有 call_id、state_version 和 state，同一状态版本产生的 state_changed、media_ready 或 media_closed 会冲突，outbox 的唯一约束会静默吞掉后续事件。

- 为不同逻辑事件设计独立、稳定、可重放的身份，覆盖事件类型和必要的媒体状态版本。
- 呼叫状态、媒体状态版本及对应事件在一致事务中提交，不能状态成功而事件永久缺失。
- 进程中断或差分重放后，补齐应有事件，并保持同一逻辑事件 ID 稳定。
- 验证同版本多事件、状态落库后事件入库失败、重复更新、并发 CAS、终态与媒体关闭事件的顺序。
