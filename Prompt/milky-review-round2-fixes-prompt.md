## 1. 非法 DH 公钥必须成为受控通话失败

涉及 Core/CallService.cs、Core/SyncService.cs、Media/BigIntegerDiffieHellman.cs 和 tests/FakeBackend.cs。

- 当前 SharedSecret 对非法公钥抛 ArgumentException，而呼叫处理和后台同步未完整处理此异常。默认宿主行为可能因此停止整个服务。
- 验证 DH 参数、生成元、公钥长度及协议要求的安全范围。复用成熟实现或经过审查的验证逻辑，不只判断字节长度。
- 将确定的非法对端数据转换为稳定业务错误，终止对应呼叫、释放本地资源并可靠结束或对账后端状态。保持其他消息和呼叫的同步运行。
- 暂时网络或存储失败继续按可重试路径处理，不能将所有异常统一吞掉，也不能只修改宿主策略掩盖后台任务已经退出。
- 假后端通过真实 DH 运算生成合法 g_b，不能直接使用随机 256 字节冒充公钥。另设确定性的恶意或非法输入用例。
- 回归至少覆盖公钥为 0、1、p-1、p、长度错误和其他违反协议范围的值。通过真实后台服务入口注入，确认服务仍可处理下一条普通消息。
- 多次执行完整测试，排除随机生成非法公钥导致的偶发失败，保留每次结果。

## 2. 被叫必须验证初始 g_a_hash 和最终指纹

涉及 CallService.ApplyAsync、DeriveKeyAsync，以及通话持久状态。

- 首次有效来电时持久保存主叫承诺的 g_a_hash、呼叫身份及必要协议上下文。后续更新不能覆盖初始承诺。
- 收到主叫公开值后，在启动媒体和宣布就绪前验证 SHA-256(g_a) 与最初承诺一致，再验证 DH 公钥并派生共享密钥、校验最终指纹。
- 不接受缺失、格式错误或不符合当前协商阶段要求的指纹。不能通过 fingerprint != 0 的条件绕过必需检查。
- 缓存共享密钥时保存其验证来源与阶段，后续 active 更新仍须遵守协议校验，不能因命中缓存跳过最终验证。
- 对不匹配值受控结束通话，保证不启动引擎、不发 media_ready，并可靠处理后端占线。
- 回归包含正常被叫流程、与最初承诺不符但与新更新自洽的 g_a、错误指纹、缺失指纹、跨呼叫材料替换及重启后验证。不能只让假后端检查主叫发出的哈希。

## 3. 接听操作先持久化密钥，再提交后端

涉及 CallService.AcceptAsync 和接听扩展请求处理。

- 当前每次接听重新生成私钥，且在 accept_call 成功返回后才保存。响应丢失、进程退出或主叫确认抢先到达时，本地会缺少匹配的私钥。
- 在请求后端前，事务式保存该呼叫的接听操作、加密私钥、原 g_b、协议提案和操作阶段。
- 同呼叫重复或并发接听复用同一材料，避免重新生成。处理扩展 request_id 的参数校验与冲突语义。
- 明确后端已接听但本地未收到结果的恢复路径。后台差分读取密钥时，要么拿到已提交的原材料，要么等待可恢复阶段。
- 回归覆盖正常接听、同键并发、丢响应、提交前后进程中断、active 更新抢先到达及挂断与接听竞争。通过重启恢复证明密钥仍与已提交 g_b 匹配。

## 4. 媒体恢复必须独立于信令状态推进

涉及 CallService.ApplyAsync、EnsureMediaAsync 和媒体状态持久化。

- 当前先将信令状态推进 active，再启动媒体。失败后媒体关闭，重放 active 更新又因 Rank 判断直接返回。
- 分离信令状态、媒体启动阶段和媒体恢复任务。信令状态没有前进时，仍能恢复尚未成功的媒体操作。
- get_call_config、网络、引擎暂时启动失败应进入有界重试。确定的密钥或协议错误应终止，避免无限重试。
- 将真实引擎连接与音频可用条件纳入 media_ready 判定。仅 StartAsync 返回并不足以自动证明远端音频已就绪，除非引擎契约明确保证并有测试。
- 同一呼叫并发更新不得创建多个引擎实例。挂断、取消和账号变化要终止待启动及待重试任务，迟到成功不能复活已结束呼叫。
- 回归包含一次配置 500 后恢复、引擎首次启动失败后恢复、同一 active 更新重放、状态提交后进程中断和恢复期间挂断。

## 5. 挂断待确认记录需要真正的后台执行者

涉及 CallService.EndAsync、ReconcileAsync、CallStore 和 Host/Composition.cs。

- 当前 ReconcileAsync 只查询其他实例的呼叫，也只在启动与 CLI 登录时调用。本实例 reconcile_state=pending 没有自动处理路径。
- 实现受账号作用域约束的持久后台对账，处理本实例挂断待确认、其他进程遗留及需要恢复的操作，使用有界退避和可观测状态。
- 持久保存待执行的结束原因及必要参数，丢响应后仍对账同一呼叫。按真实后端错误码区分已结束、权限拒绝、格式错误和暂时失败，不能把任意 400 当作已结束证据。
- 挂断结果未知时及时关闭本地媒体及现有媒体连接、撤销令牌，后端占线继续保持待确认记录。后端确认前不报告已经释放线路。
- 后台工作具备并发保护、取消和旧账号隔离。释放本地资源的失败不能让持久挂断任务丢失。
- 回归包含 discard 500、提交后丢响应、无需用户手工重试即可自动结束、同 generation 重启、旧进程残留、重复终态及恢复后双方重拨。

## 6. 事件连接绑定账号与会话代际

涉及 EventBus、EventSubscription、OutboxDispatcher 和 MilkyEndpoints 的 SSE/WebSocket 循环。

- 当前订阅只包含 consumerId 与游标，单例总线向所有订阅广播。缓存修复不等于事件连接隔离。
- 每个订阅显式绑定服务器、账号和会话代际。事件信封、队列路由、最小位点计算及消费位点写回均使用同一作用域。
- 退出、重新登录或切换账号时取消旧订阅与连接，清理旧队列。最后写出前再次验证上下文，丢弃迟到事件。
- 旧连接不能收到新账号事件，也不能把新账号 event_seq 写进旧账号的消费位点。
- 同时检查媒体连接的账号、代际和令牌失效行为，账号变化后旧连接不得继续使用媒体权限。
- 回归使用真实 HTTP SSE 和 WebSocket 连接，覆盖 A 切换 B、同账号新 generation、排队消息迟到、连接建立期间切换及相同 consumerId 跨账号复用。

## 7. 消息与呼叫租约加入所有者隔离

涉及 IdentityStore 的消息操作租约、CallStore 的呼叫操作租约及全部调用方。

- 当前只有 lease_until，没有所有者标识。旧执行者可在租约过期后释放或覆盖新执行者持有的租约和状态。
- 获取租约返回唯一 lease_token 或具备同等隔离能力的递增版本。续租、释放、阶段写入及完成操作均按当前所有者条件更新，并检查影响行数。
- 租约到期被接管后，旧执行者不能继续提交状态或释放新租约。必要时续租，并在网络结果返回后重新核对持有权。
- 获取租约时排除不应继续执行的终态，租约获取后重新检查操作结果。完成记录不得被迟到失败或 submitted 写入降级。
- 后端网络请求仍使用原 random_id、原请求及原密钥材料，租约机制与后端幂等共同保证恢复。
- 回归包含 A 取得租约、A 超时、B 接管、A 释放、C 尝试领取，以及 A 迟到成功/失败覆盖 B 结果的场景。消息与呼叫分别测试，使用可控时序。

## 8. 补齐 WebSocket 客户端可使用的确认与恢复位置

涉及 MilkyEndpoints.RunWebSocketAsync、消费位点、协议扩展和文档。

- 当前只发送 envelope.Payload，客户端拿不到 envelope.Seq。SendAsync 完成即 Ack 并持久化，客户端在处理前断线时无法请求准确恢复位置。
- 设计并实现明确命名、版本化的 Nyarugram 扩展，提供稳定事件标识、消费序号和客户端确认或显式恢复契约。
- 扩展模式区分已发送与已确认位点。确认绑定账号、代际和消费者，校验顺序及范围，防止错误确认跳过未交付事件。
- 保持标准 Milky 事件兼容，分别说明普通应用端与扩展应用端的保证。真实应用端对新增字段、扩展帧及重连流程的处理应有互操作验证。
- SSE 的 Last-Event-ID、WebSocket 的恢复位置、同 consumerId 并发连接、保留窗口和缺口通知必须自洽。缺口不能静默跳过。
- 回归覆盖发送成功但客户端未确认即断线、客户端处理后确认、确认丢失、重复确认、非法超前确认、重启、保留期过期及两个消费者进度不同。
